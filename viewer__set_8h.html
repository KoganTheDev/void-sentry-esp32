Detailed Description

Which stream viewers should receive which frame (pure C++20, natively tested).

A viewer that is still receiving (busy) is skipped, so it never builds a backlog and always gets the newest frame next - this is what keeps stream latency low. NOT thread-safe; StreamBroadcaster locks around it.
