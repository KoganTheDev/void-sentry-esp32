Detailed Description

Motion detection and persistent single-target tracking on camera frames.

Each frame: JPEG -> 40x30 gray (jpeg_gray), MotionDetector, Tracker. The pipeline state is allocated once in internal RAM by begin() (~12.6 KB at 40x30; tracking measured 0.6 ms there versus 1.1 ms in PSRAM); nothing is allocated per frame. After start_task(), a dedicated "detect" task (core 1, priority 3) owns the pipeline and calls detect_object() on every new published frame; the snapshot and stats getters and reset() may be called from any task.

void CameraDiffDetection::reset ( )
overridevirtual

Request a reset of detector and tracker plus an Idle snapshot.

Sets a flag and wakes the detection task. Safe from any task. Called from loop() (core 1, priority 1) the higher-priority detect task preempts the caller, applies the reset and publishes Idle before reset() returns, so it is synchronous in practice. The task's 200 ms wait timeout remains a backstop.

◆ start_task()

bool CameraDiffDetection::start_task ( FrameStore & store)

Create the "detect" task (core 1, priority 3, 4096 B stack) and subscribe it to the store.

The task sleeps until FrameStore::publish wakes it, then analyses the newest unseen frame. Idempotent. Call after begin() and after the frame pipeline is running; store must outlive this object.

Returns
false if begin() has not succeeded, the task cannot be created or the store has no free subscriber slot.
