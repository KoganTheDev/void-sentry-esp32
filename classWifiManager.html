Detailed Description

Glue between the pure prov::WifiPlan and the Arduino WiFi stack.

Driven only from loop() through maintain(), which never waits for a join or scan to complete (scans are async, WiFi events (arduino_events task) only set atomic flags, and maintain() turns them into plan events). All WiFi API calls and plan calls happen in maintain()/begin(), and maintain() holds one FreeRTOS mutex for its whole pass, including WiFi driver calls that take a while (WiFi.mode/softAP when the hotspot starts or stops, WiFi.begin, starting a scan) and NVS writes (save_nets after a join).

status() (behind /api/wifi/status, which the HUD polls) never takes that mutex: maintain(), begin() and add() publish a copy of its fields into a spinlock-guarded snapshot whenever they may have changed, and status() copies that. The rarer, user-initiated accessors (scan(), saved(), add(), forget()) still share the network list, PIN guard and scan cache with maintain() under the mutex, so a call that lands during one of those slow driver calls waits for it, and the single httpd task (every /stream send and /commands reply) waits with it. add() and forget() also hold the mutex across their own NVS writes, which blocks loop() in maintain() for that time.

◆ status()

WifiManager::Status WifiManager::status ( )

Snapshot of mode, SSID, IP, whether a PIN is set and the last failure.

Never takes the manager mutex (one short spinlock copy), so it cannot wait behind maintain(). The copy is the one published at the end of the last maintain() pass (or by begin()/add()), so it lags the live state by at most one pass. It holds no password or PIN.
